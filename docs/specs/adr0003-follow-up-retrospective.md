## Agent-environment improvements, ordered by severity

These findings apply the repository's retro skill and writing-for-agents guidance. Existing check scripts and CI were inspected first. The repository already has substantial CI guardrails; the improvement is to strengthen the specific boundary where evidence was missing, not duplicate those checks or enlarge AGENTS.md.

1. **High — information access: surface authentication readiness at the start of acceptance planning.** Existing ADC preflight/recovery and isolated acceptance helpers correctly detected expiration, but the human passkey step prevented the final live gate. Run those existing preflights before scheduling a long implementation/acceptance session and arrange the human verification while independent work proceeds. A future unattended trusted test environment needs an explicitly approved identity arrangement; this session did not broaden IAM or bypass authentication.

2. **Medium — automated checks: isolate native test output from editor compilation.** Local Maven incremental runs repeatedly encountered editor-generated classes containing `Unresolved compilation problem`, while Maven reported no compilation needed. Clean reactor compilation restored passing tests; clean CI passed. An isolated Maven output directory or a deterministic local check for invalid compiled stubs would remove this false failure. This is a tooling improvement proposed for future work, not a new coding-style rule.

3. **Medium — automated checks: protect eligibility and action identity at the native/browser seam.** Review found a generic Pro fallback offered without its Loner condition, and a Mascot choice that consumed Pump/Show instead. Native negative-eligibility and coexistence fixtures now protect those repairs and are wired into current Java/browser CI. Keep testing the actual catalog against native conditions and the resource identified by each label; engine acceptance alone does not prove an offered option is correct.

4. **Medium — automated checks: mount production playback and use pointer/visual evidence.** A wrapped camera toolbar intercepted a hosted Blitz click, a portaled dice label lost its screen-reader styling, and a pending reroll's dice vanished after animation. Production-component/hook regressions and captures now cover these failures, including late transcripts and reconnect. Continue checking actual pointer targeting, retained pixels and required controls rather than relying only on DOM presence or helper components.

5. **Low — navigation and tool economy: keep the boundary map and bound fixture diagnostics.** Reroll behavior spans native RollMechanic, StateMechanic, end-turn expiry, prompt projection, HUD and durable log. The focused audit provides that map. Large fixture equality failures produced excessive expected/actual output; the new accounting test reports the generated artifact path with bounded diagnostics. A shared fixture comparison helper could report the first differing field without dumping the whole document. Reuse the existing source/ledger pointers and affected-test manifest instead of copying requirements into more steering files.

Independent reviews caught the cross-file eligibility/resource defects before merge. Their findings received executable regressions. No evidence from this session justifies another global AGENTS.md rule or removal of a specific steering rule. Recommendations above that are not described as delivered checks remain proposals.
