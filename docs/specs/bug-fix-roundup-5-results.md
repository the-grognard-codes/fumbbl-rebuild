## Review findings resolved

- PR validation exposed a pre-existing random-kickoff assumption in `NegativeConditionMarkersTest`: legacy recovery was expected to erase all conditions, even when native state contained Dodgy Snack. Explicitly injecting that condition reproduced the CI failure. The test now compares every player's native-derived conditions before and after recovery while removing legacy projection fields; all seven condition tests pass. No product code changed for this correction.
- Multiple Block's offered-dice fallback could overwrite a partial native reroll. Target identity and matching faces now preserve the report's explicit rerolled indexes.
- The native reroll report contains only newly rolled values for logging. Added `blockRollAfterReroll` carries the complete resulting pool without changing those log values; browser tests include captured native ordinary/Multiple Block report sequences and suppress the following full-pool confirmation animation.
- Punt continuation waits for movement, rerolls and opposing reactions, then rechecks the authoritative player, endpoint, action and turn before sending the direction. Failed movement and disconnected/suspended state discard the continuation.
- Native sideline Punt needed to clear its consumed crowd dialog; Eye Gouge needed the original pre-push coordinate to survive follow-up publication and recovery.
- Existing playback assertions that required pauses after successful rolls were updated to the approved continuous behavior.
- The coach HUD test now asserts automatic chat closing and Enter reopening. A dice-effects test's 100 ms clock setup race was fixed before the final browser run; its animation and lifetime assertions remain unchanged.
- The teammate browser test still opened Debug before using the newer public camera control, making that control inaccessible. The test now operates the public control directly; its throw/kick, cancellation, camera and landing assertions pass.
- The full follow-up gate exposed a five-second navigation timeout in the reroll browser harness before gameplay assertions began. Navigation now has a separate 30-second limit for loading the production module graph; the five-second interaction limit and deliberate delayed-readiness assertions are unchanged. The focused readiness stress test passed after this correction.
- Owner follow-up found that Punt's spent declaration metadata disabled the combined declaration/targeting entry. Declaration and targeting now have separate menu entries. The native commands remain unchanged; the targeting companion uses the shared 30 px control styling and 44 px touch target. The new browser regression starts before declaration, publishes the spent declaration with legal native directions, opens/cancels/reopens targeting, and confirms exactly one direction. All existing Punt fixtures now include the spent metadata and `puntNow` command that the earlier fixture omitted. Desktop and touch screenshots were visually inspected.

- On the Ball previously projected adjacent-square commands instead of a normal route activation. Its accepted state now connects to route planning and the strict browser decoder accepts native reaction movement forecasts only in the relevant reaction modes. Captured native snapshots exercise this boundary. The confirmation control measures the reaction bar so both remain accessible on narrow screens.
- Finishing an On the Ball player without moving previously left the native skill unused, allowing the same player to be offered again. BB2025 now consumes that opportunity on explicit finish. Both computer policies distinguish skill acceptance, player finish, jump toggles and reaction completion.
- Defender interruptions exposed missing transient dodge and jump flags during checkpoint recovery. BB2025's movement steps now preserve that state for On the Ball. Independent review caught and resolved compatibility with older checkpoints: absent optional keys remain absent during exact roundtrip validation. Current and legacy checkpoints are checked with Diving Tackle accepted and declined and Tentacles-interrupted jumps that succeed or fail. A successful Tentacles hold also cancels restored walking/jumping checks, without consuming additional dice.

## Environment retrospective

The repository's `retro` and `writing-for-agents` skills were applied to this session. Existing build, typecheck, native-rule and browser gates caught the editing and integration mistakes; no additional generic checklist is proposed.

- Compare sandbox and host authentication before requesting another login. The supplied execution-environment instructions already cover this; `gh` worked with the existing host credential store.
- Keep final browser sources fixed while the complete browser gate runs, and wait for test processes to exit before `npm ci`. Four concurrent browser workers hit a cold-load timeout on this machine; two workers were used for the final run. These are invocation choices, not new product requirements.
- Use captured native report sequences at the browser boundary. Synthetic full-pool reroll fixtures alone missed the distinction between rerolled values and the resulting pool; the new native fixture closes that gap.
- Use captured native movement forecasts and strict protocol decoding for reaction-route tests. Verify both current and legacy checkpoint roundtrips when adding persisted step state; uninterrupted movement alone cannot establish recovery parity.
