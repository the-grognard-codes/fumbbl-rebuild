## Scope and how to read the catalog

The registry selects **183 distinct Step IDs** from 185 concrete source
definitions. [StepFactory](../../ffb-server/src/main/java/com/fumbbl/ffb/server/step/StepFactory.java) uses [Scanner](../../ffb-common/src/main/java/com/fumbbl/ffb/util/Scanner.java); BB2025 priority
overrides COMMON for HAND_OVER and DROP_FALLING_PLAYERS. Both overridden
definitions are listed separately. The catalog covers every concrete literal
`getId()` definition under server/step, not just the architecture-map hotspots.
It also lists all 38 concrete sequence generators plus ActivationSequenceBuilder,
and every server-main source file constructing a Dialog*Parameter or the terminal
dialog factory call. Abstract reroll/skill providers are included explicitly.

Phase letters below are **proposed semantic ownership**, because native code
does not currently store these phases. A=turn play/activation resolution; C=turn cleanup; D=drive end;
H=half end; F=match end; S=drive start/kick-off; T=turn start; P=pre-match prelude.
An individual player activation is contained in A and may end without C.
Caller-dependent steps do not acquire a phase simply from their package name.

Mode columns enumerate literal TurnMode references in that source, **not** an
exhaustive allowed-mode assertion. No literal reference means the step inherits
the caller's current mode. Shared generic decisions inherit the same causal
phase, even when their constructor lives outside a Step. Information/error and
terminal statistics dialogs are listed too, without calling all of them choices.
This is static source coverage, not dynamic proof that every skill/option path
has executed or that every native dialog has a current browser renderer.

## Mode and evidence limits

The complete declared mode vocabulary is [TurnMode](../../ffb-common/src/main/java/com/fumbbl/ffb/TurnMode.java). REGULAR and
BETWEEN_TURNS do not alone distinguish A/C/T. SETUP does not alone distinguish
old-turn cleanup from new-drive setup. Interception/Dump Off, bomb modes,
SAFE_PAIR_OF_HANDS, TRICKSTER, HIT_AND_RUN, RAIDING_PARTY, PLACE_CARRIED_PLAYER,
THEN_I_STARTED_BLASTIN and selection modes are nested continuations. WIZARD
inherits its causal InducementPhase path; end-turn spells can still be A-resolution. PERFECT_DEFENCE and SELECT_GAZE_TARGET remain enum
declarations; this catalog does not infer an active BB2025 branch from their
names. Recovery must preserve the actual native mode, not rewrite it to a phase.

The production IDs equal the complete [StepId](../../ffb-server/src/main/java/com/fumbbl/ffb/server/step/StepId.java) enum except its TEST
sentinel, which has no production step implementation and is not a match phase.
The source census checks 183 selected IDs, both COMMON overrides, 39 generator/
builder definitions and all 87 dialog-constructor/factory provider files.
It checks linked files/symbols and literal generator-ID resolution. Dynamic
option/skill reachability, V2 renderer support, exact boundary emission, timing,
expiry and restored ordering still require the later implementation matrix.
Static coverage is not universal runtime compliance. No #547/#550 implementation
or tests were started by this document.
