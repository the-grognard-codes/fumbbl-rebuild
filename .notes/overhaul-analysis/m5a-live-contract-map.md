# M5a live match contract and art map

Status: captured on 2026-09-25 from the active `/browser/v2` stack. This is the M5b route and M5c board input, not a new protocol version. The nested `setupState.state` remains version 1 inside the v2 transport envelope. The strict browser decoder is `browser-client/src/setup-protocol.ts`; the server producer is `SetupSession.view`. Match preparation is a separate `preparedMatch` response.

## Frozen roster to art

`FrozenTeam` stores each team's `rosterId` and each frozen player's `positionId`, `slot`, `jerseyNumber`, name and skill IDs. The current live `players[]` publishes only `slot`, name and role, so it cannot reliably choose a roster/position sprite, particularly for an authorized spectator who never received both private prepared-team documents. The preview PNG sets under `browser-client/public/preview/humans-64px-chibi-v1` and `orcs-64px-chibi-v1` are numbered aesthetic variants, not a stable mapping from engine `slot` or `positionId`. M5c needs a small public presentation identity from the frozen match (roster and position per player, or a reviewed server-selected art key) with versioned decoder, actor/spectator projection tests, restored-match compatibility and unknown-art fallback. Never guess that `home` is Human or that `away` is Orc. Existing Human catalog is the supported live content; Orc preview art does not imply supported Orc gameplay. Asset provenance/public-use disposition remains an R6 release item.

## Captured Blitz evidence

`browser-client/test/fixtures/m5a-blitz-projections.json` contains eight secret-free real-engine actor and spectator projections from `CoreTurnActionsTest.continuousBlitzPublishesConsistentActorAndSpectatorCheckpoints`. The test starts at (7,7), declares Blitz, selects a defender at (11,7), moves through (8,7), (9,7), (10,7), blocks, and reaches the push choice. Match ID is normalized; no bearer, account, invitation or request ID is saved. The test regenerates the fixture and checks exact bytes, matching public players, ball, phase, revision and current shared public decisions at each checkpoint. The action sequence is sourced from current `SetupSession`/`CoreTurnActions`, not the parity demo reducer.

The live contract has no route geometry or success percentages. Movement choices expose one destination square and may include a dice target in a human label, but not a whole proposed path or authoritative probability. M5d may animate already selected server-issued steps decoratively; percentage labels wait for the separately tracked `/browser/v2` odds contract in `TODO.md`.
